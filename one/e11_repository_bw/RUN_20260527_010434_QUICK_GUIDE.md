## 💡 可能的问题根源

### 1. NHEFT 的 getDLInfo() bug（最可能，70%）
- 返回了异常大的 dl_finish_time
- 导致 calcEST() 计算出巨大的 EST 值
- 任务被安排到很晚，需要额外 vCPU

**症状**:
```
NHEFT: EST 比 DHEFT 大 100 倍
NHEFT 使用 12 vCPU，DHEFT 仅 7 vCPU
```

**修复**: 检查 NHEFT.findBestPlan() 中的浮点数计算

### 2. 特殊的 SFC 结构（中等可能，20%）
- 这 4 个 seeds 可能生成了特殊的 DAG 结构
- 比如"所有任务都很小"导致算法行为异常

**修复**: 用 100 seeds 看是否问题消失

### 3. 时间精度问题（小概率，10%）
- 极快的完成时间（1.6s）可能导致浮点数精度问题
- epsilon 值可能不够合理

**修复**: 调整 EPS 常量或时间计算精度
